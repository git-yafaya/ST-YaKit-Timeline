# YaKit-理脉

YaKit-理脉的技术名称是 `YaKit-Timeline`，版本 `0.2.3`。它是一个运行在 SillyTavern 中的第三方扩展，用来根据故事日期自动管理当前角色世界书里的时间线条目。

项目地址：<https://github.com/git-yafaya/ST-YaKit-Timeline.git>

## 它解决什么问题

当一本角色世界书里有“序章”“港口篇”“远行篇”等不同阶段的条目时，手动开关这些条目容易遗漏。YaKit-理脉会在配置阶段帮助你整理条目，在运行阶段读取 AI 最终回复中的 `<wlog>` 故事时间，并按确定的日期边界切换已确认纳管的条目。

插件只按年、月、日进行时间线匹配；时、分只用于显示和记录。

## 安全边界

- 只读取当前角色卡实际绑定的一本世界书，不根据角色名、世界书名称或聊天额外挂载项猜测目标。
- 自动模式只修改用户确认纳管条目的 `enabled` 状态。
- 不修改世界书正文、Comment、Key、Secondary Key、Order、Depth、Position、Probability、Strategy 或绑定关系。
- AI 分析只读取当前绑定世界书条目的 `entryId`、`comment`、`content`；这里的 `content` 指世界书条目正文，不是聊天消息正文。
- 快速扫描完全在本地进行，不调用 AI；深度扫描才会把条目发送给所选 AI 接口。
- 聊天正文只在解析最后一条 AI 回复的 `<wlog>`，或用户点击“获取当前时间”时读取，不会作为 AI 分析材料。
- `<wlog>` 缺失或损坏时，插件保持原故事时间和世界书开关；日期冲突、配置无效或无法唯一匹配时，相关分组保持原开关并提示用户，不自动猜测。

## 明确不做什么

V1 不提供以下能力：

- 跨世界书合并时间线组；
- 运行阶段让 AI 猜测当前日期；
- 自动修改世界书正文或其他原生字段；
- 生成前的世界书保险校验；
- 插件级“暂停全部自动控制”、撤销上一次切换或 Dry Run；
- Claude/Gemini 专用协议和国际化；
- 不经用户操作的后台自动更新。

## 前置条件

使用前请准备：

1. 已安装并能正常运行 SillyTavern。
2. 已选择一个角色卡。
3. 该角色卡实际绑定一本世界书。插件按“一张角色卡一本世界书”工作。
4. 世界书中已有带有明确日期或时间顺序的时间线条目。
5. 如果使用深度扫描，准备好可用的 SillyTavern 主 API，或一个 OpenAI Compatible 副 API。
6. 角色使用的提示词或预设能够让 AI 在最终回复中输出合法的 `<wlog time="...">`。没有有效 `<wlog>` 时不会自动切换世界书。

SillyTavern 扩展清单不声明最低客户端版本；实际可用性仍取决于当前 SillyTavern 提供的扩展 API。

## 通过 GitHub URL 安装

在 SillyTavern 的扩展管理器中选择“安装扩展 / Install Extension”，粘贴下面的仓库地址并安装：

```text
https://github.com/git-yafaya/ST-YaKit-Timeline.git
```

安装完成后按 SillyTavern 提示重新加载页面。左下角魔法棒菜单中会出现带时间线图标的：

```text
YaKit-理脉
```

点击该项即可打开插件。

## 快速上手

### 1. 绑定角色世界书

先在 SillyTavern 的角色卡设置中绑定你要管理的那一本世界书，然后打开左下角魔法棒菜单进入 YaKit-理脉。顶部会显示当前角色、当前世界书和当前故事时间。

### 2. 准备时间线条目

为不同故事阶段准备独立的世界书条目，并在正文中写出可核对的日期。例如下面是虚构的短示例：

```text
17年3月1日，雾港灯塔重新点亮。
```

插件不会把这些示例写回世界书，也不会替你改写原条目。

### 3. 选择扫描方式

进入“AI分析”页面：

- “快速扫描”：本地筛选明显候选并生成草稿，不调用 AI、不消耗模型 Token。候选默认未选中且为低置信度，不会直接纳管；请先勾选需要管理的条目，再逐项点击“检查”，确认标题、开始日期和边界并保存。
- “深度扫描全部条目”：把当前世界书的条目交给 AI，生成分组、排序、展示标题、日期和边界建议。大世界书会自动分批分析。

### 4. 检查并编辑草稿

扫描结果只是草稿，不会立即接管世界书。请检查并按需要修改：

- 分组名称；
- 条目顺序和分组归属；
- 展示标题；
- 内容开始日期和切换边界；
- 低置信度、冲突和其他警告。

也可以查看条目正文的只读预览。确认前，旧配置继续保持，不会因为扫描结果直接改变世界书开关。

### 5. 确认并应用

确认草稿无误后点击“确认并应用”。只有应用后的条目才会进入时间线管理。如果当前聊天已经保存了合法故事时间，应用后会立即校准自动组，可能马上改变受管条目的启用状态；没有合法时间时只保存配置，不改世界书开关。

之后可以在“分组”页面继续新建、重命名、合并、拆分、删除和排序分组；删除分组不会创建“未分组”兜底，也不会修改世界书正文。

### 6. 让 AI 输出合法 `<wlog>`

AI 生成完成后，最终回复应包含完整的时间标签。下面是虚构的短示例：

```xml
<wlog time="🕒时间:17年3月2日/09:10">
雾港线进入第二幕。
</wlog>
```

插件只在 AI 回复完成后读取最后一条 AI 消息。流式生成中不会切换。若同一条消息有多个标签，会从后往前取最后一个合法时间。

### 7. 自动切换或手动获取时间

- 自动模式：日期变化后，插件按已确认的边界在组内关闭旧条目、开启当前条目；同一自动组同一时刻最多启用一个受管条目。
- 手动模式：插件停止干预该组，你可以自由组合条目开关。
- “获取当前时间”：只重新读取最近一条 AI 回复中的合法 `<wlog>`。适合手动编辑正文后重新同步；读取失败时保持现状。

时间倒退会等待你确认；较大的向前跳跃按新日期计算，并按设置显示提醒。无法唯一匹配时不会强行切换。

## 主要页面和功能

- **总览**：查看当前世界书、各时间线组、运行模式和当前生效条目。
- **时间线**：搜索和筛选条目，查看生效状态、异常、人工修改标记和只读正文预览；手动模式下可操作条目开关。
- **分组**：新建、重命名、合并、拆分、删除分组，调整组顺序，移动和排序条目。
- **AI分析**：选择快速扫描或深度扫描，查看进度、取消扫描、检查草稿、处理置信度和差异，最后确认并应用。
- **日志**：查看当前聊天的运行日志，以及 AI 扫描、配置操作、API 测试和插件错误等系统日志。
- **设置**：设置主题、切换通知、AI 接口、模型和参数、破限提示词、固定提示词、时间跳跃提醒、配置导入导出和扩展更新。

顶部的“获取当前时间”按钮和上下文栏按钮作用相同。

## AI、破限提示词和副 API

### 主 API

默认使用“跟随主 API”，调用 SillyTavern 当前配置的主接口。可以获取模型列表并选择模型；模型留空时跟随主 API 当前模型。

### 副 API

“副 API”使用单独配置的 OpenAI Compatible 接口，需要填写 API URL、API Key 和模型名称。设置页支持获取模型和测试连接。

YaKit-理脉与 YaKit-纪实共享副 API 连接。任一插件中保存的连接，另一插件都可以直接读取和选择。API Key 保存到 SillyTavern Secrets，不写入插件普通配置。

### 自定义提示词

“自定义提示词”是一级容器，包含“破限提示词”和“固定提示词”两个二级容器。发送顺序为：

```text
破限提示词 → 固定提示词 → 当前分析请求
```

内容与内置预设相同时显示“默认”，修改后显示“已修改”。两个编辑弹窗都可以使用“重置”恢复预设。破限提示词只在你明确了解并愿意承担相关风险时使用。

## 更新方式

打开“设置”页面时，插件会通过 SillyTavern 检查 GitHub 扩展版本。发现新版本后只提示你，不会自行更新。

点击“更新”后会立即执行更新；更新成功会自动刷新页面，不需要第二次确认。若更新失败，页面会保留错误信息。

## 数据隐私

- 插件是纯前端 SillyTavern 扩展，没有 YaKit-理脉自有服务器。
- 快速扫描不发送数据到 AI。
- 深度扫描会把当前绑定世界书条目的 `entryId`、`comment` 和 `content` 发送到你选择的 SillyTavern 主 API 或副 API。使用深度扫描前，请确认你信任该接口服务商。
- 深度扫描不会发送当前或历史聊天消息、角色卡正文、Persona、示例对话、`chatMetadata` 或 `<wlog>` 消息内容。
- 全局设置和世界书时间线配置由 SillyTavern 的扩展设置保存；当前聊天的时间、组模式和运行日志保存在聊天元数据中。
- 配置导出不包含 API Key。API Key 默认由 SillyTavern Secrets 管理；运行日志和系统日志不会主动记录完整 API Key、聊天正文或世界书正文。分析失败页的“最后一次原始输出”来自模型，模型可能在异常结果中复述输入内容，复制、保存或反馈前请自行检查并打码。

## 当前限制

本版本以 PC 端为主要验收和使用目标。移动端适配尚未完全完成，不能将移动端视为已完整支持；如果手机或平板上入口无响应，请优先使用 PC 端。
